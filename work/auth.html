지마켓지마켓 · 옥션 · ESMPLUS 공통 인증

통합인증 서비스

3인 팀에서 프로젝트를 주도하며 다섯 인증 유형, 외부 업체 연동, 공통 세션과 관리자 기능을 모두 구현했습니다. 지마켓·옥션·ESMPLUS가 같은 인증 서비스를 사용하고, 운영자는 배포 없이 인증 설정과 업체별 요청 비율을 조정합니다.

어떤 상황이었나

지마켓과 옥션의 인증 기능이 서비스마다 따로 있었습니다. 인증 로직 하나를 고치려면 여러 곳을 같이 손봐야 했고, 인증업체는 한 곳에 의존하고 있어서 그 업체에 문제가 생기면 할 수 있는 일이 별로 없었습니다. 비용을 조정할 여지도 없었습니다.

소유인증, 본인인증, 계좌인증, 정보인증, 기업인증을 하나의 서비스로 묶었습니다. 정보인증에는 아이디·비밀번호와 소셜인증이 포함됩니다. 3인 팀에서 프로젝트를 주도하며 인증 모듈부터 외부 업체 연동, 공통 세션과 관리자 기능까지 전체를 구현했습니다.

인증을 모듈로, 설정은 어드민으로

인증 유형별 기능을 한 서비스 안의 모듈로 정리하고, 어떤 도메인이 어떤 인증을 어떤 설정으로 쓰는지는 코드가 아니라 어드민 설정으로 뺐습니다. 새 서비스가 인증을 붙일 때 코드를 고치는 대신 설정을 추가하면 되는 구조를 목표로 했습니다.

외부 인증업체와의 통신도 윈도우 설치형 모듈에서 API 토큰 방식으로 바꾸고, On-Premise ASP.NET에 있던 인증 기능을 Spring Boot로 옮겼습니다.

운영자가 손댈 수 있는 인증

인증 업체별 요청 비율을 관리자 화면에서 조정하도록 만들었습니다. 운영자는 업체 장애나 이용 비용을 고려해 신규 요청의 비중을 배포 없이 바꿀 수 있습니다. 변경된 비율은 신규 요청에 적용하고, 진행 중인 인증은 기존 흐름으로 처리합니다.

다섯 인증 유형이 공유하는 세션

세션은 특정 인증이나 E쿠폰만을 위한 기능이 아니라 통합인증의 공통 기능입니다. UUID로 세션을 조회하고, 관리자 화면에서 정한 유효기간을 기준으로 활성 여부를 확인하도록 구현했습니다.

인증별 처리 로직은 각 모듈이 담당하고, 세션 유효성 확인은 공통으로 사용합니다. E쿠폰에는 본인·소유인증을 연동해 공통 세션으로 인증 내역과 이력을 관리했습니다.

연동부터 운영까지 맡은 범위

다섯 인증 유형의 API와 외부 업체 연동, 공통 세션, 도메인 설정과 업체별 요청 비율 관리 기능을 모두 구현했습니다. 계좌인증은 유입 경로별 은행 정보 API와 연동 가이드를 제공하고, E쿠폰은 세션 상태 때문에 인증이 진행되지 않는 문의까지 확인했습니다.

오픈 직전 연동 명세가 바뀐 경험을 계기로 회의록·설계 문서·진행 상황을 공유하며 연동 서비스와 변경 사항을 맞췄습니다.

돌아보면

공통 인증 로직에 운영 설정을 더하면서 업체 전환이 코드 배포와 분리됐습니다. 비율 조정은 신규 요청에 적용하며, 진행 중인 인증의 처리와는 구분했습니다.

회사 프로젝트의 소스 코드는 공개하지 않습니다. 구조도는 업무 흐름을 설명하기 위한 개념도입니다.
